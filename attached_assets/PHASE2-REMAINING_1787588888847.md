# Worldsmith — Phase 2, remaining steps

The gpt-image-2 migration closed Phase 2's steps 1 and 3. Three remain, and they are ordered by
dependency, not size.

`POST /v1/production-packages` (worldsmith.ts L291) is the last `NOT_IMPLEMENTED` endpoint in
Worldsmith. Everything below leads to closing it.

---

## Step A — Extract the generation core

Generation logic lives inside `spec-preview-service.ts`, tangled with board compositing. Pull the
model-facing half into `lib/worldsmith/image-generation.ts`:

- config resolution (`WS_IMAGE_MODEL`, quality, size via `image-targets.ts`)
- the `generateImage` call and its error handling — **keep the non-fatal-by-design behavior**
- `uploadFileToNotion` + property attach
- audit-row writing, including the `success_placeholder` trick that deliberately fails its own
  idempotency match so a skipped generation retries next call

Leave in the preview service only what is genuinely about the board: the Victorian style preamble, the
`fit: inside` composite into `CONCEPT_IMAGE_AREA`, `getFittedConceptImageBox`, the detail crops, the
caption strip.

**Do not change preview behavior while extracting.** It works and it is tested. If a preview test goes
red during this step, the extraction is wrong — not the test.

**Done when:** existing preview tests pass untouched, and the new module has no import from
`spec-board-template.ts`.

---

## Step B — Reconcile the canon-record generation path

`POST /v1/editorial/canon-records/generate-image` (worldsmith-editorial L1123) is live and works. It
predates the migration, so **check first whether it still uses `callDallE`** — if it does, it is
running on the deprecated alias and silently discarding the effective-size metadata.

Migrate it onto the module from step A in the same pass. Two implementations of one call is how the six
readiness calculations happened; three would be worse.

**Watch:** this path may have its own prompt-derivation logic. Keep that — it is legitimately
different from a production spec's. Share the *call*, not the prompt.

**Done when:** every image Worldsmith generates goes through one module, and `callDallE` has no
remaining callers.

---

## Step C — Wire `production-packages`

Only now implement the endpoint. Use the orchestrator's reserved stages 13–18 (the pipeline is numbered
to 22 and currently implements 1–12 and 19–22).

Requirements — the preview service already demonstrates every one of these, so copy its shape:

- **Idempotent** on the hash, which now carries effective model/size/quality. A repeated call must not
  re-bill.
- **Dry-run mode**, matching the preview service's: report the target dimensions from
  `image-targets.ts`, the model, the quality, and an estimated cost, without calling anything.
- **Audit row per attempt** carrying provider, model, model version, effective size, quality, filename
  and upload id.
- **Fatal upload, non-fatal generation** — same ordering. Nothing advances before the artifact lands.
- **A status distinct from the preview's.** A spec with a concept board is not a spec with final
  artwork; neither may satisfy the other's gate.

**Done when:** a dry run reports the plan, a real run produces an uploaded asset with a complete audit
row, and a second identical call returns the first asset without billing.

---

## Two things Phase 2 must not do

**Do not make generation fatal to a compile.** Compiling a prompt and generating an image are separate
today, which is why a failed OpenAI call never blocks a spec from being reviewed. Keep that.

**Do not let a generated asset advance a status a human has not seen.** The board exists so a person
approves the direction before final artwork is made. If generation becomes automatic on compile, the
board becomes decoration.
