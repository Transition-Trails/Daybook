# Replit task — admin colour token drift

Paste this whole file to Replit. Mechanical and low-risk: eleven files declare their own colour
constants instead of reading the admin tokens. Most are close enough to look fine in isolation
but wrong side-by-side, and several are **cool greys in a system whose borders and muted text are
warm**.

`artifacts/admin/src/index.css` is the source of truth. It already defines the full set under

## 0. Add one missing token

`#4A6080` is **Slate** — a real brand colour (it is named in the palette comment at the top of
`index.css` as the secondary), but it has no `--admin-*` token, which is why four files hardcode
it. Add it next to `--admin-blue`:

```css
--admin-slate: #4A6080;
```

Do not add any other new token. Everything else below maps onto tokens that already exist.

## 2. Two of these are visible changes, not no-ops

Everything above is a same-or-near-same swap except the `MUTED` rows. Call these out when you
report back:

- **`hsl(216 15% 52%)` → `var(--admin-muted)`** is a cool grey becoming warm brown-grey
  (`#7A6A57`). This is the intended correction — the admin surface has no cool greys — but it
  changes how `NewRecipe`, `Releases` and `ProductRecipes` read. Expected, and correct.
- **`#4A6080` → `var(--admin-slate)`** is not a colour change at all (same hex), just a token.
  The four `build/` steps keep their current appearance.
