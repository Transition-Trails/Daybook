# Worldsmith — Wave 4: structured typography

Replace the prose the font picker writes into compiled fields with a structured field the compiler
reads selectively. This is the last of the three Wave 4 decisions that needs code.

---

## What happens today

`FontLibraryPicker.appendFontReference()` appends four lines of plain text into whatever field it is
attached to:

```
Daybook Font: Spectral
Curated roles: heading 700, body 400
Available variants: 4
Source notes: Chosen for the 1920s ledger look; pairs with Instrument Sans
```

That text lands in **`visualPalette`** (WorldSmithHome L1786–1788), and `visualPalette` is compiled
verbatim into the prompt as `[VISUAL PALETTE]`. The same picker is wired into canon `visualNotes`,
`NewStyleGuideFlow`, and `EditorialDocumentEditor` — all compiled.

So an image model currently receives **"Available variants: 4"** and **"Source notes: …"**. The first
is catalog metadata about a font file. The second is a note written for a human colleague. Neither
describes anything that can appear in a picture.

Two lines *are* useful — the family and the curated roles. That is the whole problem: the useful and
the useless arrive as one indivisible blob of prose.

There is a second, quieter defect. Selection state is derived by string search:

```ts
const selected = value.includes(`Daybook Font: ${font.familyName}`);
```

Edit that sentence while writing, and the picker forgets the font is selected. Prose is being used as
a database.

---

## The shape to build

**A structured field beside the prose field, not instead of it.** The prose stays exactly as it is for
human authoring; the font choice moves out of it.

### 1 — Schema

Add a `typography` JSONB column to the three tables whose fields the picker writes into:

```
worldsmith_worlds     ADD COLUMN IF NOT EXISTS typography JSONB NOT NULL DEFAULT '[]'
ws_canon_records      ADD COLUMN IF NOT EXISTS typography JSONB NOT NULL DEFAULT '[]'
ws_style_guides       ADD COLUMN IF NOT EXISTS typography JSONB NOT NULL DEFAULT '[]'
```

Shape — an array, because a world normally has a heading face and a body face:

```ts
type TypographyChoice = {
  fontId: string;                                    // ws catalog id — the real key
  family: string;                                    // denormalized for display + compile
  roles: Array<{ role: string; weight?: string }>;   // from curatedPairings
};
```

`fontId` is what makes this better than prose: the selection is a key, so renaming a font in the
catalog no longer orphans anything, and `selected` becomes `typography.some(t => t.fontId === font.id)`.

**Deliberately not stored:** `variants` count and `notes`. Those live on the catalog record and can be
looked up when a human wants them. Excluding them at the schema level is what makes the compile
correct *by construction* rather than by filtering — nothing downstream has to remember to strip them.

### 2 — Picker

`FontLibraryPicker` stops taking `value: string` / `onApply: (font) => void` writing prose, and
instead takes:

```ts
value: TypographyChoice[];
onChange: (next: TypographyChoice[]) => void;
```

Clicking a font toggles it in the array. `appendFontReference` and `fontReferenceText` are deleted —
keep them only if something outside Worldsmith imports them.

### 3 — Editor

Render the choices as chips **above** the rich-text field, so the author still sees "Spectral ·
heading 700 · body 400" while writing, but it is not *in* the document. Each chip gets a remove
control. This is the part that makes the change feel like an improvement rather than a removal.

### 4 — Compiler

Emit a `TYPOGRAPHY` block from the structured field:

```
[TYPOGRAPHY]
Spectral — heading 700, body 400
Instrument Sans — body 400, caption 500
```

**Decided: its own `[TYPOGRAPHY]` section**, not folded into `[VISUAL PALETTE]`. Cleaner to test, and
preserving today's shape buys nothing — every prompt hash changes the moment the prose stops carrying
font text, so there is no compatibility to protect. Place it immediately after `[VISUAL PALETTE]` in
the assembly order, before materials, and add it to the legacy `sections` compat map as
`typography: ""` so nothing reading that map breaks.

### 5 — Migration and backfill

The existing prose already has font text baked into it, so the backfill has to both extract *and*
strip. Follow the pattern established in `worldsmith-editorial-migration.mjs`:

- Match `Daybook Font: (.+)` in each `visualPalette` / `visualNotes` / `content`, look the family up
  in the fonts catalog to recover `fontId` and `curatedPairings`, and write a `typography` entry.
- Remove the whole four-line block (and its `<p>…</p>` wrapper in rich-text fields — see
  `appendFontReference`'s HTML branch) from the prose.
- **Run it once, inside the `if (column.rowCount === 0)` block.** Not with a `WHERE typography = '[]'`
  guard — an empty array is a legitimate author state, exactly like `section = 'general'` was. That
  guard was wrong last time; do not repeat it.
- Where the family cannot be matched to a catalog row, **leave the prose alone** and log it. A font
  reference that cannot be resolved is better left visible to a human than silently deleted.

**Done when:** a world whose `visualPalette` contained a font block compiles with the family and roles
present, `Available variants` and `Source notes` absent, and the palette prose otherwise unchanged.

## Test first

```
typography-field.test.ts
  · a TypographyChoice compiles to family + roles only — no variants, no notes
  · the compiled prompt carries a [TYPOGRAPHY] section positioned after [VISUAL PALETTE]
  · the backfill extracts a font block and removes it from the prose
  · an unmatched family is left in the prose and logged
  · toggling a font twice leaves typography unchanged (idempotent)
```

---

## Why this shape, briefly

The same pattern already solved a bigger problem in this codebase: canon `emotional_register` and
`sensory_clauses` became structured fields, and the compiler emits them selectively. Typography is
that pattern applied one more time. Once it is in, three things stop being possible — catalog metadata
reaching an image model, a font choice being lost by editing a sentence, and a compiled field being
edited by a widget the author did not think was writing to it.
