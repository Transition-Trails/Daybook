### 10a — the palette

`DEFAULT_SWATCHES` (L124) is a list of six named swatches — Antique Ivory, Parchment Cream, Sage
Gray and so on — and L541 falls back to it whenever the spec has none:

```js
const effective = ((colorSwatches?.length ?? 0) > 0 ? colorSwatches! : DEFAULT_SWATCHES).slice(0, 6);
```

This is the highest-consequence substitution on the board. A reviewer sees six named swatches beside
the words "Palette must feel cohesive, muted, and authentically aged" and approves a palette nobody
chose. Render an explicit empty state instead, and delete `DEFAULT_SWATCHES` once nothing references
it — leaving the constant in place invites the fallback to come back.

Note you now have a real palette library (`GET /worlds/:worldId/palette-library`). Reading from it
here would be a genuine improvement, but it is **not** this step: a world-level palette is not the
same claim as a spec-level one, and substituting it silently would be the same bug wearing better
clothes. If you want that, wire it explicitly and label the zone as inherited from the world.

## Step 15 — bump the template version, and reconcile the format

**File:** `artifacts/api-server/src/lib/worldsmith/spec-preview-service.ts` L41

```diff
-const TEMPLATE_VERSION = "v2";
+const TEMPLATE_VERSION = "3.1";
```

The gate is still on `v2` while `spec-board-template.ts` L18 now exports `TEMPLATE_VERSION = "3.1"`.
The mismatch is **wider than when it was found** — it was `v2` vs `v3.0`, and the template has since
moved again. Every board generated under `v2` still satisfies the idempotency gate, so nothing
regenerates, so none of the Wave 2 fixes appear on any spec that has already been compiled.

**Two constants, two formats, one meaning.** `spec-board-template.ts` exports `"3.1"`;
`spec-preview-service.ts` declares its own `"v2"` locally. Do not just bump the string — **import the
template's constant and delete the local one.** That removes the whole class of failure rather than
resetting it:

```diff
-const TEMPLATE_VERSION = "v2";
+import { TEMPLATE_VERSION } from "./spec-board-template.js";
```

The idempotency row, the `templateVersion` column write, and the `"Template Version"` field on the
board all read the same symbol after this, so a template change can never again leave the gate behind.

**VERIFY:** regenerate a previously-compiled spec. The new board shows the corrected fonts (Wave 1
step 09), no invented palette or constraints (step 10), and real emotional registers (step 11). The
audit row records template version `3.1`.

**EXPECT:** a one-time regeneration across every previously-compiled spec, with the DALL·E cost that
implies. That is the intended effect — those boards are currently stale and being read as current.

**THEN:** the guard. Importing the constant makes drift impossible, so a test asserting the two match
becomes unnecessary — but add one asserting the *audit row* carries the current version, so a future
refactor that reintroduces a local constant fails loudly.
