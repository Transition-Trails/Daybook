## Step 05 — Fix the canon-grounding check (one character)

**File:** `artifacts/api-server/src/routes/worldsmith-editorial.ts`, line 101, inside `computeReadinessScore`

The first clause passes for any spec whose canon dependency is not `"None"`, which makes the two
grounding clauses unreachable for exactly the specs the check exists to police. A Canon Defining spec

```diff
-      dep !== "None" || canonIds.length > 0 || !!spec.styleGuideId,
+      dep === "None" || canonIds.length > 0 || !!spec.styleGuideId,
```

**VERIFY:** a Canon Defining spec with no canon records and no style guide now scores lower than the
same spec with a style guide linked.

**DECIDE:** after this change, line 101 and line 103 (`dep === "None" || canonIds.length > 0`) become
close relatives — 101 is 103 plus a style-guide escape hatch. That is defensible as a lenient check
beside a strict one, but it is now accidental rather than designed. If only one is wanted, keep 103
and delete 101. Do not do this silently; ask first.

## Step 07 — Test current state before historical state (reorder 3 lines)

**File:** `artifacts/api-server/src/routes/worldsmith-editorial.ts`, `derivePipelineStatus`, lines 115–131

`compiledPromptStatus` is a stored field written at compile time. Because it is tested first, a spec
that compiled and then lost its canon records still reports `compiled`, and `published` is unreachable
— publishing requires a compile, so the branch above always returns first.

Current order:

```ts
if (spec.compiledPromptStatus === "Compiled") return "compiled";
if (spec.notionPageId && spec.syncedAt)       return "published";
// …
if (needsCanon && canonIds.length === 0)      return "blocked";
```

Replace with:

```ts
if (needsCanon && canonIds.length === 0)      return "blocked";
if (spec.notionPageId && spec.syncedAt)       return "published";
if (spec.compiledPromptStatus === "Compiled") return "compiled";
```

Leave the `draft` checks and the two score thresholds where they are, after these three.

**VERIFY:** a spec with `compiledPromptStatus: "Compiled"`, `canonDependency: "Canon Reference"` and
zero canon records returns `blocked`. A spec with `notionPageId` and `syncedAt` set returns `published`
rather than `compiled`. On the readiness board, the published column starts populating.

## Step 08 — Compile the payload the validator normalized (four edits)

**Files:** `lib/worldsmith/types.ts`, `lib/worldsmith/validator.ts`, `lib/worldsmith/orchestrator.ts`

This is the highest-value change in the wave. `validatePayload` applies the whole alias map
(`paper_and_materials → materials`, `card_role → asset_role`, `front_layout + back_layout →
composition`) to a payload object and then returns only a `ValidationResult` — the normalized object is
discarded. The orchestrator re-parses the raw text and compiles that instead. So an aliased field passes
validation and vanishes from the compiled prompt.

### 1. `types.ts` — add to the `ValidationResult` interface

```ts
payload?: Partial<ParsedPayload>;
```

### 2. `validator.ts` — add a parameter to `buildResult` and include it in the return

```ts
function buildResult(
  specId: string,
  payloadVersion: string,
  valid: boolean,
  errors: ValidationError[],
  warnings: ValidationError[],
  payload?: Partial<ParsedPayload>,   // add
): ValidationResult {
  // … compiledPromptStatus logic unchanged …
  return {
    production_spec_id: specId,
    payload_version: payloadVersion ?? "",
    valid,
    compiled_prompt_status: compiledPromptStatus,
    errors,
    warnings,
    payload,                          // add
  };
}
```

### 3. `validator.ts` — the final return of `validatePayload`

```diff
 const valid = errors.length === 0;
-return buildResult(specId, spec.payloadVersion, valid, errors, warnings);
+return buildResult(specId, spec.payloadVersion, valid, errors, warnings, payload);
```

Leave the early returns alone — the ones for missing payload version, unsupported version and empty
payload fire before parsing and all return `valid: false`, so nothing downstream compiles.

### 4. `orchestrator.ts` — stage 9, replace the second parse

```diff
-const { payload } = parsePayload(spec.promptPayload);
+const payload =
+  payloadValidation.payload ?? parsePayload(spec.promptPayload).payload;
+
 const compiled = compilePrompt(
   chainWithBible,
   payload as Parameters<typeof compilePrompt>[1],
 );
```

**VERIFY:** compile a legacy PP-1.0 record that uses `paper_and_materials` instead of `materials`, and
confirm the compiled `fullPrompt` now contains a `[MATERIALS AND LIGHTING]` section with that content.

**EXPECT:** previously-compiled records will report a new prompt hash on next compile. That is correct
— the prompt genuinely changed. If anything keys off the old hash it will regenerate once.

## Step 06 — Make canon mutations refresh both the kanban and the library (5 sites)

**Files:** `CanonBoard.tsx`, `CanonLibrary.tsx`, `CanonRecordDetail.tsx`, `CanonRecordEditor.tsx`,
`WorldsmithCanon.tsx`

The board invalidates `["editorial-canon-board"]`; the other four invalidate
`["editorial-canon-library"]`. Nothing invalidates both, so each surface shows stale data after an edit
made in the other.

**Note:** invalidating a shared `["editorial-canon"]` key does NOT work. React Query matches query keys
element by element, not by string prefix, so `["editorial-canon"]` does not match
`["editorial-canon-board", worldId]`. Use a predicate instead.

Replace every canon-mutation invalidation — both key variants — with:

```ts
qc.invalidateQueries({
  predicate: (q) =>
    String(q.queryKey[0] ?? "").startsWith("editorial-canon"),
});
```

Leave the relations invalidations (`["editorial-canon-record-relations", recordId]`) as they are; the
predicate already covers them.

**VERIFY:** move a card between columns on the kanban, switch to the library without reloading — the
status is already correct. Then reverse it: change a status in the record editor and check the board.

## Step 09 — Point the spec board at the fonts that exist (do this last)

**File:** `lib/worldsmith/spec-board-template.ts` — `FONT_DIR`, `fontCss()`, `renderSpecBoardToPng`

`FONT_DIR` resolves to `lib/worldsmith/fonts`, which is not a directory. The real font files are one
level up in `lib/fonts`:

```
Spectral-400.woff          Spectral-700.woff
Spectral-Regular.ttf       Spectral-Bold.ttf
Instrument_Sans-400.woff   Instrument_Sans-700.woff
InstrumentSans-Regular.ttf InstrumentSans-Bold.ttf
```

The current `@font-face` rules ask for `spectral-regular.woff`, `spectral-bold.woff`,
`spectral-italic.woff`, `instrument-sans-regular.woff` and `instrument-sans-bold.woff` — none of which
exist under those names.

### 1. Fix the directory

```diff
-const FONT_DIR = path.join(
-  path.dirname(fileURLToPath(import.meta.url)), "fonts");
+const FONT_DIR = path.join(
+  path.dirname(fileURLToPath(import.meta.url)), "..", "fonts");
```

### 2. Hand resvg the directory directly

Correcting the paths alone may not be enough: resvg builds its font database from `loadSystemFonts`,
`fontDirs` and `fontFiles`. It does not fetch `@font-face` `src` URLs the way a browser does.

```ts
const resvg = new Resvg(svg, {
  font: {
    loadSystemFonts: false,
    fontDirs: [FONT_DIR],
    defaultFontFamily: "Spectral",
  },
  fitTo: { mode: "width", value: BOARD_W },
});
```

### 3. Rewrite `fontCss()` against the real filenames

**ASK FIRST:** there is no italic Spectral in `lib/fonts` in any format, and the board uses italic in
three places (the world attribution, the emotional-intent phrases, the palette note). Either add an
italic Spectral, or point the italic `@font-face` at `Spectral-400.woff` and accept upright text.
Do not pick one silently.

**VERIFY:** render one board before and after and compare them visually. This step is not verified by a
test — look at the artifact. Once it renders correctly, add a test asserting one known glyph width so it
cannot regress silently.
