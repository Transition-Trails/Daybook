Build three distinct, clickable design concepts for the WorldSmith landing page inside Daybook.

This is the home page for WorldSmith in Daybook. It must be informative, actionable, role-aware, and designed for daily operational use.

Do not build three minor visual variations of the same dashboard. Create three meaningfully different information architectures so we can compare approaches before selecting one for production.

Do not change the existing Daybook data model or production workflows unless required to support the prototypes.

==================================================
PRIMARY GOAL
==================================================

Create three functional landing-page concepts that help users:

1. Understand the current state of WorldSmith.
2. See what is actively being produced.
3. Identify worlds, collections, or assets that need attention.
4. Filter the entire page to one World.
5. Open a selected World quickly.
6. Start setting up a new World.
7. Configure and verify required integrations.
8. Navigate to production, review, assets, runs, and administration.
9. Take the next appropriate action without hunting through multiple screens.

The landing page should answer:

• What is happening?
• What needs attention?
• What should I do next?
• Which World am I looking at?
• Are the required integrations healthy?
• What is ready, blocked, under review, or complete?

==================================================
USERS TO DESIGN FOR
==================================================

The landing page must support three personas.

----------------------------------------
1. CREATIVE DIRECTOR
----------------------------------------

Primary needs:

• See the creative health of each World.
• Understand what is currently being produced.
• See assets awaiting human review.
• Identify canon, style, or specification blockers.
• Open Product Specification previews.
• Review visual direction and consistency.
• Filter to a single World or Volume.
• Move quickly into reviews and approvals.
• See recent visual assets and production milestones.

Most important actions:

• Review specification preview
• Review generated artwork
• Approve or return for revision
• Open a World
• View blocked production items
• Inspect style and canon dependencies
• Start or continue a production batch

----------------------------------------
2. STORE END USER
----------------------------------------

This is a business or store user who needs visibility into products and deliverables without managing the technical system.

Primary needs:

• See which Worlds and product collections exist.
• Understand what is planned, in production, ready, or published.
• See product completeness.
• Open approved previews and finished assets.
• Understand what products are approaching release.
• Filter by World, collection, Volume, or product status.
• Find files and approved product assets quickly.
• Avoid being overwhelmed by technical configuration.

Most important actions:

• Open a World or collection
• View product progress
• View approved assets
• View release readiness
• Find product files
• See what is coming next
• Report a product issue or request

----------------------------------------
3. DAYBOOK ADMIN
----------------------------------------

Primary needs:

• Create and configure a World.
• Connect Notion, Google Drive, image providers, and other required services.
• Check integration health.
• Identify failed runs or synchronization problems.
• See records missing required configuration.
• Manage users, permissions, providers, and environment settings.
• Open logs and retry failed operations.
• Confirm that Daybook is resolving stable Asset IDs correctly.

Most important actions:

• Set up a new World
• Configure integrations
• Test connections
• View failed runs
• Retry synchronization
• Review incomplete configuration
• Manage providers and system settings
• Open audit logs

SHARED PAGE REQUIREMENTS

----------------------------------------

• Collection or Series

• Search Worlds
• Clear filter
• Open selected World

WORLD SETUP

World setup should include:

   • Primary Style Guide

3. Storage

4. Integrations

6. Completion
   • Setup summary

   • Open the new World

Allow the user to save an incomplete setup and resume later.

Include counts or summaries for:

• Not Started

• Ready for Review

• Approved

• Failed runs

Show:

• Current production batches

• Items awaiting human review

Use plain-language labels and explain unusual statuses with tooltips.

----------------------------------------
WORLD HEALTH
----------------------------------------

Create a useful World health model.

A World can be:

• Healthy
• Needs Attention
• Blocked
• In Setup
• Inactive

Calculate or derive health from available signals such as:

• Required integrations connected
• Required Style Guide present
• Canon governance established
• Production Specifications populated
• Prompt compilation failures
• Reviews awaiting action
• Failed runs
• Missing storage configuration
• Stale activity

Display the reason behind the health status.

Do not show a mysterious score without explaining it.

----------------------------------------
ACTION CENTER
----------------------------------------

Include a prioritized action area.

Examples:

• 4 Product Specification previews awaiting review
• 2 assets returned for revision
• 1 World missing its Google Drive folder
• 3 failed synchronization runs
• 7 Production Specifications ready to compile
• 1 Canon Reference requires approval
• Volume I is 82% complete

Every item must include a direct action.

Examples:

• Review
• Resolve
• Retry
• Configure
• Compile
• Open World
• View Batch

----------------------------------------
NAVIGATION
----------------------------------------

Provide direct access to:

• Worlds
• Production
• Reviews
• Assets
• Runs
• Integrations
• Settings

The landing page should not attempt to replace these workspaces. It should summarize them and route users to the right place.

Daybook should consume and operationalize approved WorldSmith outputs. It should not become the authoritative editor for WorldSmith canon or replace the Living Archive.

CONCEPT 1: COMMAND CENTER
==================================================

Create a dashboard-first concept called:

WorldSmith Command Center

Design intent:

A compact operational cockpit for users who want to understand the entire system quickly.

Recommended structure:

TOP BAR

• WorldSmith title
• Global World selector
• Search
• Create New World
• User role indicator
• Notifications

FIRST ROW: KEY METRICS

• Active Worlds
• Items In Production
• Awaiting Review
• Blocked
• Release Ready
• Failed Runs

SECOND ROW

Left:
Action Center

Right:
Integration Health

THIRD ROW

World Health table or cards showing:

• World
• Health
• Current collection or Volume
• Production progress
• Awaiting review
• Blockers
• Last activity
• Open World action

FOURTH ROW

• Production pipeline visualization
• Recent Product Specification previews
• Recent approved assets

ROLE BEHAVIOR

Creative Director:
Emphasize reviews, blockers, recent visuals, and production progress.

Store End User:
Emphasize products, release readiness, approved assets, and upcoming collections.

Daybook Admin:
Emphasize integrations, failed runs, incomplete setup, and configuration.

Strength of this concept:

Maximum operational visibility and rapid triage.

Potential risk:

Could feel dense to less technical users.

==================================================
CONCEPT 3: GUIDED WORKSPACE
==================================================

Create an action-oriented concept called:

WorldSmith Guided Workspace

Design intent:

Lead the user toward the most important next step rather than presenting a dense dashboard.

Recommended structure:

WELCOME AREA

• Personalized greeting
• Current role
• Selected World
• Brief system summary
• Primary recommended action

PRIMARY NEXT ACTION

Display one dominant action based on role and system state.

Creative Director examples:

• Review 4 specification previews
• Approve Volume I visual direction
• Resolve a canon blocker

Store End User examples:

• Review products nearing release
• Open approved Volume I assets
• Check release readiness

Daybook Admin examples:

• Complete Wychcombe integration setup
• Resolve 2 failed synchronization runs
• Configure image provider

SECONDARY ACTIONS

Show the next 3 to 5 prioritized tasks.

WORLD PROGRESS JOURNEY

Display each World as a progression:

Setup
→ Governed
→ In Production
→ In Review
→ Release Ready
→ Published

Show exactly where each World is and what is preventing progression.

QUICK START

• Create a World
• Continue World setup
• Open selected World
• Start production batch
• Review assets
• Configure integrations

ACTIVITY STREAM

Show meaningful recent activity, not raw system noise.

Strength of this concept:

Approachable, role-focused, and highly actionable.

Potential risk:

Users may need another click to see full operational detail.

==================================================
VISUAL DIRECTION
==================================================

The page should feel like a refined creative production platform.

Use:

• Warm archival neutrals
• Restrained botanical or editorial details
• Clear modern information hierarchy
• High readability
• Generous spacing
• Strong but quiet status indicators
• World imagery where it adds value

Avoid:

• Fantasy game UI
• Heavy parchment textures behind data
• Overly ornate controls
• Dense enterprise-dashboard clutter
• Excessive gradients
• Decorative elements that impair scanning
• Generic admin-template appearance

The interface may echo WorldSmith's archival identity, but operational clarity comes first.

• A user can focus on one World.
• A user can start the Create New World wizard.

• The concepts can be compared without changing the production home page.
• WorldSmith canon remains governed outside Daybook.
