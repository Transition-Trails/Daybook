# Worldsmith — Phase 2 closeout

Phase 2 is done. Verified at `b39f8148`:

- **`POST /api/v1/production-packages` is implemented** (worldsmith.ts L293) behind
  `requireAuth + requireSuperAdmin`, running `operation: "compile_and_generate"`. No
  `NOT_IMPLEMENTED` remains anywhere in the routes.
- **Idempotency is enforced in the database**, not just in code — `worldsmith_production_packages`
  carries a UNIQUE index on `(production_spec_id, prompt_hash)`. Combined with the hash now carrying
  effective model, size and quality, a repeat call cannot re-bill.
- **`runFinalArtwork` resumes rather than regenerates.** `getExistingProductionPackage` treats
  `success`, `generating`, `uploaded_status_pending`, and `upload_failed`-with-an-upload-id as
  finishable — so a failed status write costs a status write, not a second image.
- **Statuses are distinct** — `production_art_status: "not_started" | "artwork_review"`, separate
  from the preview's own status. Neither can satisfy the other's gate.
- **Cost is real.** The package row stores `estimated_cost_usd` and `actual_cost_usd`, and
  `admin/src/lib/worldsmith/cost-estimate.ts` derives the displayed figure from the record. The
  hardcoded dollar literals are gone, and the effort line now reads "usually under two minutes;
  provider time can vary" instead of asserting a flat number.
- **Migration is tracked and tested** — `0008_worldsmith_production_packages.sql`, with a test that
  applies it twice and asserts the second run changes nothing, and that a legacy `worldsmith_runs`
  table is repaired without touching existing rows.
- Admin tests cover the call and the `artwork_review` response.

## Two small things left, both documentation

### 1 — The memory file still teaches the deprecated function

`.agents/memory/dalle-image-generation.md` (and its entry in `MEMORY.md`) says:

> `callDallE(prompt, options?)` ... Uses **gpt-image-1** ... Returns `data:<mime>;base64,...`
> Import as `import { callDallE } from "../lib/ai-proxy";`

All three details are now wrong or stale: the model is `gpt-image-2` via `WS_IMAGE_MODEL`, the current
function is `generateImage`, and it returns `ImageGenerationMetadata` alongside the data URL — the
deprecated alias returns only the string, silently discarding the effective size and quality that the
prompt hash depends on.

An agent following this file today would write code that hashes incorrectly. **This is the same class
of problem that cost a full handoff written against the wrong model's capabilities** — a stale name in
a document, believed.

Rewrite it around `generateImage`, name the metadata return, and record that `WS_IMAGE_MODEL` is the
switch. Rename the file to `image-generation.md` and update the `MEMORY.md` line.

### 2 — Remove the deprecated alias

`callDallE` at `ai-proxy.ts` L329 has no remaining callers — every generation path goes through
`generateImage` via `image-generation-service.ts`. It was kept as a compile-safety net during the
migration and that migration is finished.

Delete it in the same commit as the memory-file rewrite, so there is no way to reach the
metadata-discarding path.

**Done when:** `callDallE` returns no matches repo-wide, and the memory file describes
`generateImage`.
