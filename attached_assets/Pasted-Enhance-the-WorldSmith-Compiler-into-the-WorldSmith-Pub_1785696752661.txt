Enhance the WorldSmith Compiler into the WorldSmith Publishing Engine.

The compiler has matured beyond simply assembling prompts. The next iteration should feel like a governed publishing workflow where each stage produces an inspectable artifact and prepares the asset for the next stage.

This feature is a UX and workflow refinement. Do not change the underlying compiler logic unless explicitly required to support these improvements.

==================================================
VALIDATION REFINEMENT
==================================================

The current warnings are mixing governance recommendations with actual compilation concerns.

Replace with three categories.

--------------------------------------

ERROR

Compilation cannot continue.

Examples:

Missing Component Specification

Missing Payload Version

Broken Relation

Missing Style Guide

------------------------------------------------

WARNING

Compilation completed but quality may be affected.

Examples:

Missing Front Prompt

Missing Optional Prompt Module

Canon Recommendation

------------------------------------------------

RECOMMENDATION

Modernization or best practices.

Examples:

Legacy Payload Format

Suggested Migration

Optional Prompt Module

Payload Optimization

Recommendations should not visually compete with Errors.

==================================================
ACCEPTANCE CRITERIA
==================================================

The Publishing Engine should feel like a governed publishing system rather than a prompt compiler.

Users should immediately understand:

• where the asset is in the publishing lifecycle

• what was compiled

• where each instruction originated

• whether the asset is ready for the next stage

• what action should be taken next

Validation should distinguish between:

Errors

Warnings

Recommendations

The workflow should naturally guide users from:

Compilation

↓

Inspection

↓

Specification Board

↓

Review

↓

Artwork

↓

QA

↓

Publishing

without overwhelming them with technical implementation details.

The result should be polished enough that a Creative Director, Product Manager, or Publishing Coordinator can confidently use it without understanding prompt engineering.
