---
name: Canon relation restraint
description: Editorial standard for proposing and accepting Canon relationship edges
---

Suggest only a few specific, two-sided evidence-grounded relationships tied to a current storyline, and allow no suggestions at all when the evidence is weak. Treat proposals as reviewable editorial decisions, not inferred Canon facts or automatic connections. Acceptance must not overwrite a relationship another editor has already made.

**Why:** The user explicitly cautioned that adding every plausible connection would trap future storytelling in too many commitments.

**How to apply:** When expanding Canon linking, recommendations, or bulk tools, keep sparse opt-in behavior and reject stale or conflicting additions rather than treating shared storyline membership as proof.

When different clients can create edges, all creation paths must serialize the same pair before checking for an inverse edge. Protecting only the new client leaves a race with the older manual editor.

**Why:** Directed-pair uniqueness does not prevent simultaneous opposite-direction inserts.

**How to apply:** Keep MCP and manual writes aligned when changing relationship creation, and test concurrent inverse requests rather than only sequential duplicates.
