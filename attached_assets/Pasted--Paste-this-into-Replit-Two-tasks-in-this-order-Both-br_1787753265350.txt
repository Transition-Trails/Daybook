## Task 2 — sticker shape recipes

Follow `handoff/DAYBOOK-SHAPE-RECIPES.md` exactly.

This is the larger piece: a migration, a new table, a render endpoint, validation, four seeded starter
recipes, and authoring UI inside the existing Sticker Studio hub.

Three things in that brief are non-negotiable, so re-read them before you start:

1. **No `callAi` in the render path.** The acceptance criterion is that rendering the same recipe twice
   with identical inputs produces byte-identical output, asserted by a test. If that test cannot pass,
   stop and report rather than relaxing it.
2. **The cut path is authored, not traced** — exactly one `<path data-name="cutline">` per template.
   For the ribbon recipe, assert the cut path's bounding box spans the full artwork width, which is what
   proves the tails are in the cut.
3. **Deprecate `generate/functional` for functional types in the same commit.** Do not leave two
   rendering implementations in the tree. Wave 14 deleted five duplicate studio files for this exact
   reason and the lesson should not be undone a week later.

Do not widen `STICKER_FUNCTION_TYPES`. A recipe refines a function type; it does not add one.
